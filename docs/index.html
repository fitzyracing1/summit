Summit · scanrepo v1

Software you can hold.

A printed git repo. Read the page. Scan the codes. The bytes come back as the same commit.

One booklet, one commit

The cover carries the repo name, edition, branch, commit id, tree id, and parent. Each later page is one file in monospace, plus a QR code that holds those same bytes. A later printing does not overwrite the old one. It is a new edition whose parent is the previous booklet. The shelf is the history.

Scan path

  1. Photograph every page, cover included. Do not crop the codes.
  2. Decode each QR. Cover payloads start with C|. Page payloads start with P|.
  3. Rejoin chunks. Check each blob with git’s blob <len>\0 SHA-1.
  4. Rebuild the tree and the commit. Reject the booklet if either id misses the cover.

In the repo

  • scanrepo.kind — format declaration
  • sample.scanrepo — digital master of a two-file repo
  • scanrepo-restore.py — hash check and restore

Text only. No packfiles, no deltas. A small repo is a thin booklet. A photo-heavy repo is the wrong thing to print.
